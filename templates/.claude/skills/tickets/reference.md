# /tickets — reference

Loaded **on demand**, not every session. `SKILL.md` points here by path; there is no `@file` import
in a skill body. The kit's `docs/TICKET_FORMAT.md` is the long form of this file, with the reasoning
behind each field. **The script is the ground truth for behaviour**: if this file and
`scripts/tickets.mjs` disagree, one of them is wrong — say so rather than picking one silently.

---

## Ticket format, in brief

```yaml
---
id: 42                      # int, allocated by the script ONLY. Filename is zero-padded: 0042-slug.md
slug: kebab-case            # ^[a-z0-9]+(-[a-z0-9]+)*$ — immutable once assigned
title: Human readable       # editable; the slug is not
type: feature               # feature | bug | design | chore | refactor | docs
priority: high              # high | med | low
status: open                # open | blocked | deferred | closed
size: m                     # s <30min | m 30min-2h (TARGET) | l = too big, SPLIT IT
capability: 03-tool-runs    # or null; matches docs/capabilities/NN-name.md
depends_on: [38]            # PLANNED constraints, set at ticket-write time
blocked_by: []              # DISCOVERED constraints, set mid-session. Non-empty ⇔ status: blocked
source: agent               # agent (filed by Claude) | operator (filed by the human)
created: 2026-05-12T14:30:00Z
started: …                  # stamped by `start`, omitted until then
deferred: …                 # stamped by `defer`, present iff status: deferred
closed: …                   # stamped by `close`, omitted while open
---
```

**Folders:** `tickets/open/` holds `open`, `blocked` and `deferred`; `tickets/closed/` holds `closed`.
There is no `in-progress` status — `start` stamps `started:` instead, so an abandoned session leaves
a timestamp rather than a stuck state. `tickets/index.json` is generated by the script and
committed; never edit it.

**Required body sections, all tickets:** `## Description` · `## Acceptance criteria` (checkboxes) ·
`## Notes` · `## Operator validation`.
**`bug` also needs:** `## Steps to reproduce` · `## Expected vs actual`.
**`design` also needs:** `## Options considered` · `## Open questions` — and its acceptance criteria
read *"a capability doc exists at `docs/capabilities/NN-x.md` with no open questions"*, never "the
feature works".
**`deferred` also needs:** `## Deferred` — written by `defer`, never by hand.
**Appended at close:** `## Resolution`, and the `## Operator validation` result.

`create` scaffolds every required section with `TODO`s. A scaffolded ticket validates, but a `TODO`
is not a ticket: write the sections before committing.

### `(operator)` criteria

```markdown
- [ ] (operator) The run-detail page shows the new hostnames row
- [x] (operator) Hostnames row renders on a real HTB box — verified 2026-05-15: shows both names, no wrap
```

**Before using the marker, check it is earned.** It means *a human eye or hand is the ONLY
instrument that can answer this* — not merely *"the agent has not checked it"*. A running service, an
HTTP status code, a database row, a CLI's output, anything reachable with the tools and credentials
the agent has: **the agent runs it and records the result as a smoke test.** The prefix is
expensive — it stops a close and parks work on someone who is not at their desk — so spend it only
on judgement: does it read, does it look right, does it feel right.

Two refusals hang off it:

- **Unchecked** → `close` refuses. Leave the ticket open, commit the work, and close it in a later
  session once the operator has run it. **Do not tick it to make the close pass.** A criterion
  ticked in advance is how a skill ships that never registers.
- **Ticked with no `— verified YYYY-MM-DD: <result>`** → `close` refuses, and `validate` errors in
  every folder. The evidence lives on the criterion, not only in `## Operator validation` prose.

Relaying an operator's reported result *is* the sign-off — write what they saw, dated, in their
words where you have them. Inventing one is the failure this whole mechanism exists to prevent.

### `blocked` vs `deferred`

**`blocked` is waiting on a ticket in this backlog; `deferred` is waiting on the world.** Closing the
blocker clears a `blocked` automatically and `blocked_by` names it. Nothing here can clear a
`deferred` — there is no ticket id for "upstream fixes its release" — so it carries a mandatory
reason and a mandatory runnable re-check in a `## Deferred` section instead, both enforced by
`validate`. A deferred ticket is out of the ready set and out of its capability's
`capability-tickets-closed` check, but is **named** in the audit record: a capability that passed
with deferrals must not read as one that passed clean.

`recheck` runs the re-checks and reports. It never un-defers — `resume` is typed by someone who read
the result. `resume` renames the section to `## Deferred — resumed YYYY-MM-DD` rather than deleting
it. If you want to file a placeholder ticket just so `blocked_by` has something to hold, the state
you want is `deferred`.

### `depends_on` vs `blocked_by`

`depends_on` is *"we planned this order"*; `blocked_by` is *"we hit a wall"*. Collapsing them loses
exactly the information REFLECT wants — which orderings were foreseen and which were discovered the
hard way.

## The mechanical / judgemental split

| The script decides | You decide |
|---|---|
| Which tickets are ready | Whether a ticket is worth doing now |
| The dependency order, and the waves | What a ticket actually means |
| Whether a criterion box is ticked | Whether the criterion is genuinely **met** |
| Whether required sections exist | What belongs in them |
| Id allocation, file moves, index | Acceptance criteria, approach, resolution text |
| Cycles, dangling refs, enum violations | Whether a design doc is wrong |

**Never spend tokens re-deriving something the script computes.** Reading every open ticket to work
out an order is a context tax paid every session, produces a slightly different answer each time,
and degrades silently as the backlog grows. That is why `depends_on` is a field.

## Full close procedure

**Refuse first, then act.**

1. **Verify every acceptance criterion is genuinely met.** The script refuses on any unchecked box
   and there is **no `--force`**. Do not tick a box on the ticket's behalf.
   - If a criterion is genuinely unbuildable or turned out wrong: amend it, strike it through with
     the reason (`- [x] ~~criterion~~ — dropped: <why>`), and explain in `## Resolution`. A
     criterion that was silently ticked is a criterion that never existed.
   - **`(operator)` criteria are not yours to tick.** An unchecked one means the ticket does not
     close today — that is the rule working, not an obstacle. Amending it away is the same failure
     as ticking it.
2. **`## Resolution`** — files touched, tests added, decisions and rationale, what went wrong.
   The honest record of what happened, not what was planned.
3. **`## Operator validation`** — evidence of verification, **by whoever could actually perform
   it.** Two shapes, and picking the wrong one is the common mistake:
   - **Perceptual** → name the screen and what to look at. The test is *"would two competent people
     disagree about the answer by looking at it?"* — a layout off by a few pixels, a chart that
     misleads, a message that reads wrong. Those pass every automated test. The check must be
     answerable by opening the project as it already is: **never ask the operator to construct a
     scenario or re-verify a passing test.** If a scenario is worth testing, it is worth faking — in
     a test, or against throwaway resources.
   - **Everything else** → **you run it, and write down what it proved.** Do not route a status
     code, a database row or a CLI's output to the operator. A smoke test against the real thing
     reaches strictly further than a unit test — a stub proves the right query was *sent*; only the
     real database proves it is *accepted*.
   - **"None" is allowed** for genuinely invisible work with nothing to poke — say why. What is
     never allowed is a close with neither an operator check nor a smoke test.
4. **New decisions** → append an ADR to `docs/DECISIONS.md`.
   **Never edit a settled decision to make a ticket easier.** Supersede it visibly.
5. **`tickets.mjs close <id>`** — status, `closed:` stamp, `git mv`, index regenerated.
   Refuses on a dirty tree; it exempts the ticket's own file, so ticking a final criterion is fine,
   but unrelated dirt is not. Commit that first rather than using `--allow-dirty`.
6. **Commit on its own**: `tickets(#NNNN): <title>`.
7. **Report which tickets became ready** — the script prints them. This is the handoff.

## Script commands

`SCRIPT` = `node ${CLAUDE_PROJECT_DIR}/.claude/skills/tickets/scripts/tickets.mjs`

```
SCRIPT index                       rebuild tickets/index.json
SCRIPT list [filters]              --status --type --priority --capability --size --ready
SCRIPT show <id>                   raw markdown + dependency status
SCRIPT validate                    exit 1 on errors, 0 on warnings only
SCRIPT next [--all]                highest-priority ready, ungated ticket; refuses size:l
SCRIPT waves [<capability>] [--max N]   open tickets layered into parallel waves (default 4 wide)
SCRIPT allocate                    next free id
SCRIPT create --title --type --priority [--size --capability --slug --depends --source --body]
SCRIPT start <id>
SCRIPT block <id> --on <id> [--reason "..."]       refuses cycles and unknown ids
SCRIPT unblock <id> --on <id>
SCRIPT defer <id> --reason "..." --recheck "<shell>" | --recheck-file <path>
SCRIPT resume <id> [--reason "..."]                leaves the state; never automatic
SCRIPT recheck [<id>]              run deferred re-checks and REPORT; never un-defers
SCRIPT close <id> [--allow-dirty]
SCRIPT audit <capability>          mechanical checks; exit 1 on any failure
SCRIPT audit <capability> --sections   docs this capability's tickets cite — the reading list
SCRIPT audit <capability> --record (--divergence "<res>|<ref>|<desc>"... | --no-divergences) [--force "<reason>"]
```

`--json` works on `index`, `list`, `show`, `validate`, `next`, `waves`, `create`, `audit`, `recheck`.
`create` defaults to `size: m`, `capability: null`, `source: agent`. A `<capability>` argument may be
the bare number (`3`) or the full `NN-name`.

**Ready set:**
```
ready(T) ⟺ status ∈ {open, blocked} ∧ blocked_by = [] ∧ ∀d ∈ depends_on : ticket(d).status = closed
order: priority (high > med > low) → id ascending
```
A non-empty `blocked_by` is **never** ready, and neither is a `deferred` ticket.

**The capability gate is a `next` refusal, not a readiness rule.** A ticket in capability `NN` is
**gated** while any lower-numbered capability that has tickets lacks a `pass` or `forced` verdict
as its latest audit record. `next` hands over the best *ungated* ticket and says how many were
gated; if every ready ticket is gated it refuses and names the **lowest** unaudited capability —
listing its still-open tickets if it has any, since then the audit cannot pass yet. `next --all`
lists everything, gated entries marked: the gate refuses to hand over work, it does not hide the
backlog.

### `audit` and its verdicts

`audit <capability>` reports each check as `pass`, `fail`, `error`, or **`n/a` with a reason**. The
checks:

- **Project checks** — one row per line of the `audit-checks` block in
  `docs/capabilities/AUDIT.md`: `<check-id>: <shell command>`, run through the shell from the
  project root. Exit 0 passes; nonzero fails with the last line of output; a timeout (300 s) or a
  spawn failure is `error`. A missing file, block or check is one `n/a` row saying so; a malformed
  line, duplicate id, or second block is `error`.
- **`validate`** — zero validation errors across the backlog.
- **`blocked-by-closed`** — no `blocked_by` points at a closed ticket.
- **`capability-tickets-closed`** — every ticket in the capability is closed, except `deferred`
  tickets and tickets named as `code-was-wrong` divergences in this audit's record; both exceptions
  are named in the row and the record.

**The bare form runs the mechanical half only** and records nothing. §2 design conformance and §3
operator validation are yours — `SKILL.md`'s audit procedure drives them.

**`--record` writes the result** to `docs/capabilities/NN-name.md` as a human-readable write-up plus
a one-line `<!-- audit-record {…} -->` comment the script reads back. It refuses unless:

- every mechanical check passed (`fail` and `error` both block; `n/a` does not);
- the divergence list is **asserted** — one `--divergence "<code-was-wrong|design-was-wrong>|<ref>|<description>"`
  per finding, or `--no-divergences`. Omitting it is refused: a §2 that found nothing and a §2 that
  never ran must not be indistinguishable;
- there are **no more than three** divergences (over budget ⇒ the design is stale; run a DESIGN
  session);
- the capability doc's REFLECT section — any heading containing "reflect" — has at least 200
  characters of substance, not counting `_italic_` placeholder lines or HTML comments.

`--force "<reason>"` overrides and records `verdict: forced`, never `pass`, with the reason in the
doc. Records are append-only; a re-audit adds one and the last one stands.

## Validation rules

**Errors (exit 1):** missing or unparseable frontmatter · a missing required field (`id`, `slug`,
`title`, `type`, `priority`, `status`, `size`, `capability`, `depends_on`, `blocked_by`, `source`,
`created`) · an enum violation · a filename not `NNNN-slug.md` matching `id` and `slug` · a slug
that is not kebab-case · a duplicate id · status disagreeing with the folder · `blocked_by`
non-empty without `status: blocked` (or vice versa) · a `deferred:` stamp without
`status: deferred` (or vice versa) · a deferred ticket missing its `## Deferred` section, its
`**Reason:**` line, or its fenced re-check block · a dangling `depends_on`/`blocked_by` id · a
self-edge · a dependency cycle · an `(operator)` criterion ticked with no dated sign-off (any
folder) · a missing required section (all four, plus the `bug` and `design` extras) · a required
section appearing twice (fenced lines ignored; a closed ticket may carry one `## Operator
validation` after its `## Resolution`) · a closed ticket missing `## Resolution` · `closed:` absent
when closed or present when open · a closed ticket with an unchecked criterion · a non-null
`capability` with no `docs/capabilities/<capability>.md` (only numbered `NN-name` docs count).

**Warnings (exit 0):** `capability: null` on an open `feature` · `size: l` in the ready set · an
unknown frontmatter key (preserved on rewrite, never dropped).
